# Atlas Sanctum — Economic Flow Dashboard

> **Where is money going, where is it stuck, what impact is it producing, and what is at risk of being underfunded?**

For Atlas Sanctum, the **Economic Flow Dashboard** is the screen where finance stops being abstract and starts behaving like a living circulation map for planetary recovery. fileciteturn1file0L1-L9

## Purpose

Track financial movement across regenerative systems and expose the relationship between capital allocation, regional vulnerability, and measurable impact outcomes.

> **Bloomberg Terminal × climate intelligence × impact infrastructure × systems map**

**The Economic Flow Dashboard should make one thing painfully clear:**

Where is money going, where is it stuck, what impact is it producing, and what is at risk of being underfunded?

For Atlas Sanctum, this becomes the screen where finance stops being abstract and starts behaving like a living circulation map for planetary recovery.

## 1. Core user question

**This dashboard should answer:**

Where is regenerative capital flowing right now?

Which regions or sectors are underfunded relative to risk?

Which projects are producing the strongest impact-adjusted returns?

Where are bottlenecks in deployment, disbursement, verification, or liquidity?

How do financial flows correlate with real-world restoration outcomes?

## 2. Primary users

**This dashboard is built for high-agency decision makers:**

climate investors

blended finance funds

DFIs and development banks

sovereign partners

philanthropy networks

carbon and ecosystem market operators

regulators

Atlas internal analysts

Each of these users wants a slightly different lens, so the UI must support role-based views.

## 6. Global flow map

This is the centerpiece.

### Main visualization

A world or regional map with animated capital flows.

### Layers:

regenerative investment flows

carbon market transactions

ecosystem credit issuance and purchase

climate fund disbursements

microfinance movement into communities

### Visual logic

line thickness = capital volume

line motion speed = transaction velocity

glow intensity = current activity

node size = destination capital concentration

**color meaning:**

green = healthy deployment

amber = underfunded / delayed

red = critical financing gap

blue = stable verified markets

### Interaction

**Hovering a region or flow shows:**

total inflow

total outflow

dominant funding source

funded sectors

estimated people/ecosystems affected

verification maturity

return profile

unmet need

### Example insight

Northern Kenya Watershed Zone

inflows: climate adaptation fund + watershed restoration credits

gap: drought resilience infra still 41% underfunded

bottleneck: verification delay on ecosystem outcomes

> **That is Atlas magic: not just “money went there,” but “money went there, it helped this much, and this is what is still broken.”**

## 15. UX behavior

### Interactions that matter

click a region → open regional funding intelligence

click an instrument → open market detail panel

click a KPI → highlight all related charts

hover a flow line → show source, destination, volume, lag, risk

enable compare mode → compare 2 regions / 2 funds / 2 periods

scenario mode → see projected capital needs vs current commitments

### UX principle

**The dashboard should feel like:**

overview first

anomaly next

drilldown fast

decision support always

No user should need 14 clicks to answer “why is this region underfunded?”

## 16. AI-assisted insight layer

Because this is Atlas, the dashboard should not just show data. It should interpret.

### Insight rail

**A right-side panel with machine-generated but auditable insights:**

> “Restoration capital is concentrated in 3 regions while 7 high-vulnerability zones remain underfunded.”

> “Carbon credit issuance increased 22%, but retirement volume declined, indicating demand softening.”

> “Microfinance disbursement rose in flood-prone regions, but repayment stress suggests climate shock exposure.”

**Each insight needs:**

confidence score

supporting data sources

explanation link

suggested action

This stops the dashboard from becoming a museum of charts.

## 17. States you must design for

Senior frontend truth grenade: dashboards fail in edge states, not in Dribbble screenshots.

**Design explicitly for:**

### Loading

skeleton cards

map placeholder

chart shimmer states

### Empty state

> “No flow data for selected filters”

suggested filter resets

data coverage explanation

### Partial data

missing verification

delayed market feeds

region with incomplete reporting

### Error state

source unavailable

stale feed

currency normalization failed

inconsistent impact ledger

### Trust state

**Always show:**

data source provenance

timestamp

verification quality

methodology link

Because this dashboard touches money and impact claims. That is litigation bait if it is sloppy.

## 21. What makes this dashboard special

**Normal finance dashboards ask:**

How much money moved?

**This one asks:**

Did the money move where it was most needed?

Did it produce durable ecological and human benefit?

Is the market trustworthy?

Which regions are still exposed because finance arrived too slowly or too narrowly?

Can impact become a legible, investable, liquid signal?

That is the leap from analytics to civilizational infrastructure.

## 23. The one thing most people would miss

**From an AI + frontend systems perspective, the biggest miss would be this:**

You must show misalignment, not just movement.

> **Movement alone is vanity.**

> **Misalignment is decision intelligence.**

**So the dashboard should make highly visible:**

capital vs vulnerability

capital vs deployment speed

capital vs verified outcomes

capital vs systemic risk reduction

That is the difference between “look at this impressive financial map” and “we now know where to intervene.”
